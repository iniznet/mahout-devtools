# ADR-0003: generated references are date-free and drift-checked by bytes

- **Status:** Accepted
- **Date:** 2026-01-01
- **Supersedes:** nothing

## Context

The roadmap requires three generated artefacts — the POT template, the hook
reference and (already shipped) the WordPress stubs — each with a gate that
fails when the committed file differs from a fresh generation. A gate only
works if two runs over the same source produce identical bytes. The standard
gettext POT header carries a `POT-Creation-Date`, which makes every run differ
from every other and would turn the i18n gate into a permanent red.

The divergence rule requires that a consumer's four analyzer files reference
the configuration shipped by the pinned `mahout-devtools` rather than copying
it. The rule can be enforced by executing the consumer's analyzers, which is
slow, needs the consumer's dependencies and cannot see a copy that is currently
unused; or by reading the files and the lockfile, which is fast and states the
rule directly.

## Decision

1. `GeneratedReference` renders the text and `ReferenceGate` compares it by
   bytes and reports the first differing line. The POT, the hook reference and
   their tests share this one mechanism.
2. The POT template omits `POT-Creation-Date` (and every other timestamp) so
   regeneration is byte-identical. Its gettext header is otherwise standard.
3. The hook scan and the POT scan are token-based (`token_get_all`) and never
   load the source they inspect. A public hook constant whose docblock omits
   `@action` or `@filter` throws rather than being guessed.
4. `composer config:check` proves divergence textually: the four analyzer files
   name the pinned package, `composer.json` requires it, `composer.lock` pins
   it, no local `rules/*Rule.php` copy or local `phpstan-arch.neon` exists, and
   the per-repository artifact set is present. In the producer repository the
   same command proves every shipped rule file is registered in `phpstan.neon`.
5. The shared `rector.php` and `.php-cs-fixer.dist.php` resolve their paths
   from `getcwd()`, so a consumer's `require` of the shared file analyses the
   consumer's tree. `psalm.xml` has no include mechanism, so it references the
   shared stub path and declares its own project files.

## Consequences

- A stale reference fails with the exact differing line, and the fix is the
  matching `:generate` command.
- A POT generated by a third-party tool differs only by the header timestamp;
  this is the one intentional divergence from `wp i18n make-pot` output.
- `translate_nooped_plural` is recognised but contributes no entry of its own,
  because the pair was already extracted from the `_n_noop` or `_nx_noop`
  declaration. A noop pair declared in one file and translated in another is
  therefore extracted at the declaration only.
- The divergence gate cannot execute the consumer's analyzers, so it cannot
  catch a reference path that is textually right and functionally broken. The
  consumer's own `composer check` is what runs them.
- A consumer that legitimately needs a local PHPStan `services:` entry fails
  the gate. Adding one is a change to the gate, not a local edit.
